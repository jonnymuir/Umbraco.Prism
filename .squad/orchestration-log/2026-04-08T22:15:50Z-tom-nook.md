### Summary

Produced authoritative architecture design document for the Prism Workflow Forms Engine, resolving 5 open architectural questions:

1. **Scope Boundary** — Demo framework, not production BPM
2. **Storage Model** — Hybrid NPoco + JSON fixtures
3. **Workflow Definition Schema** — State machine (7 base states)
4. **Field Group Registry** — Pluggable, tenant-isolated field schemas
5. **Demo Workflow Choice** — Information Request as canonical exemplar

### Key Decisions

- Framework focuses on demonstration and reference, not production-grade low-code designer
- NPoco tables for live state/events/tasks; JSON fixtures for definitions
- 7-state finite state machine: `Draft` → `Submitted` → `Assigned` → `InReview` → `Decision` → `Closed`
- Field groups (e.g., `RequestorDetails`, `ReviewerNotes`) authored per domain
- One canonical example: Information Request workflow demonstrating full interaction pattern

### Rationale

Keeps Prism scope manageable. Demonstrates framework contract without authoring UI complexity. Allows implementors to build domain-specific workflows without framework bloat.
