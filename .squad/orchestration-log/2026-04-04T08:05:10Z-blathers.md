## Task

Fix intermittent `System.IO.IOException` caused by a parallel MSBuild race condition on `*.dswa.cache.json` (Static Web Assets cache) files when the VS Code "C#: Full Prism Stack (Both)" compound launch configuration starts `UmbracoPrism.TestSite` and `UmbracoPrism.MockBackOffice` simultaneously — both triggering independent builds of the shared `UmbracoPrism.Core` project.

## Outcome

Race condition eliminated. Core is now pre-built once before either consumer's `dotnet run` launch adapter runs.

## Changes Made

- **`.vscode/tasks.json`** — Added new `"dotnet: build Core"` task (`dotnet build src/UmbracoPrism.Core`). Chained it as a `dependsOn` prerequisite for the existing `"Client: build"` task so TestSite's launch path pre-builds Core.
- **`.vscode/launch.json`** — Added `"preLaunchTask": "dotnet: build Core"` to the `"C#: Mock Back-Office Debug"` configuration, ensuring Core is built before MockBackOffice's dotnet launch adapter runs (becomes a fast MSBuild no-op if already up-to-date).

## Rejected Approach

`ReferenceOutputAssembly="false"` on MockBackOffice's `ProjectReference` to Core — not viable because MockBackOffice has genuine compile-time code dependencies on Core types (`UmbracoPrism.Core.Extensions`). Removing the assembly reference breaks compilation.
