### Key Implementation Decisions
1. **Subscription model uses `Genre`** (not `Topic` from design doc) — matches task spec
2. **`IPrismNotificationService` follows task method signatures**, not design doc interface
3. **FirebaseAdmin named instance** (`"prism-notifications"`) guards against duplicate `FirebaseApp` init
4. **`PrismNotificationService` registered as `Scoped`** (appropriate for `IUmbracoDatabaseFactory` consumption)
5. **Device-only registration** creates minimal credential stub (10-year expiry, empty `TokenHash`)
6. **`PrismContentPublishedHandler` reads `prismTenantId` content property** for tenant resolution (request-scoped `IPrismContext` unavailable in background handlers)
7. **Notification handler uses `INotificationAsyncHandler<T>` pattern** — consistent with all Umbraco handlers in codebase
8. **Stale FCM token cleanup is in-band** (synchronous after each batch; failures swallowed with warning log)
