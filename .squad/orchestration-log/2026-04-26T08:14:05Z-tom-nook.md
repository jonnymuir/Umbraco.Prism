### Headline Scope Decision Surfaced

**Generic `ConditionalOn` + `VisibleWhen` on arbitrary components:**
- v1 model allows any field to have conditional visibility
- v2 plan implements `ConditionalChildren` on Radios/Checkboxes only (~80% of use cases)
- Generic conditionals would require tree traversal for every render/validation

**Three options presented:**
- **Option A:** Generic conditional properties on base PrismComponent (flexible, complex)
- **Option B:** ConditionalContainerComponent wrapper (explicit, verbose)
- **Option C:** Defer to v2.1 (keeps P3 lean, ship v2 sooner)

**Recommendation:** Option C (defer to v2.1). Rationale: ConditionalChildren on Radios/Checkboxes covers canonical "Other → specify" pattern (~80% of use cases).

### Design Gaps Surfaced

1. **Component-tree validation traversal** — V2 needs recursive tree walk to find InputComponent descendants (P3 work)
2. **Component-tree authorization checks** — V2 needs role-based field visibility enforcement (P3 work)
3. **Generic conditional visibility** — Defer to v2.1 per above recommendation
4. **Summary-list + conditionally-hidden fields** — If summary references hidden field, show "Not provided" or omit (P3 blocker already flagged)
5. **Fieldset-level validation** — Can FieldsetComponent have validation rules? (defer to v2.1)
6. **Conditional children depth limit** — Warn if nesting exceeds depth 2 (P2 migrator or P4 builder)
7. **Umbraco integration doc JSON examples** — All seed workflows use v1 schema; rewrite in P2-P6 (not design gap, doc debt)
8. **Redesign doc obsolescence** — `workflow-forms-engine-redesign.md` superseded by v2 components (archive with pointer)
