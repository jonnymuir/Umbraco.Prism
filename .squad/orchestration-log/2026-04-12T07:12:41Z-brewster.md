# Orchestration Log — Brewster @ 2026-04-12T07:12:41Z

## Agent: Brewster (Umbraco Platform Specialist)

### Mission
Diagnose why Umbraco TestSite runs in Aspire without an advertised URL.

### Outcome
✅ **RESOLVED**

#### Findings
- **Root Cause:** Aspire launch-profile mismatch for `UmbracoPrism.TestSite`
- **Issue:** Aspire defaults to matching service launch profiles by name with the host (AppHost uses `https`), but TestSite uses `Umbraco.Web.UI` (non-standard). First profile was `IIS Express`, so Aspire selected the wrong one and missed the `applicationUrl`.
- **Solution Applied:** Pinned TestSite launch profile explicitly in `src/UmbracoPrism.AppHost/Program.cs`

#### Changes Made
- Updated `builder.AddProject()` call with `launchProfileName: "Umbraco.Web.UI"`
- Ensures Aspire parses correct `applicationUrl` values from TestSite's `launchSettings.json`

#### Validation
- ✅ Build passed
- ✅ Core tests passed
- ✅ TestSite should advertise URL in dashboard after AppHost restart

### Decision Recorded
Decision merged to `.squad/decisions.md` as "Aspire TestSite launch profile selection"

### Standing Effect
When Umbraco-based projects in this repo use nonstandard launch profile names, AppHost should select them explicitly rather than relying on Aspire's default launch-profile matching behavior.
