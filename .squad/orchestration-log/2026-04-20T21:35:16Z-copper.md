## Work Completed

Investigated persistent "Telemetry endpoint is unsecured" warning in Aspire 9.2.0 dashboard despite prior environment variable attempts.

### Approach

1. Read Aspire 9.2.0 source code directly instead of guessing at configuration
2. Traced warning emission in `DashboardWebApplication.cs` to root cause
3. Analyzed process boundaries and env var propagation via `DashboardLifecycleHook.cs`
4. Determined correct security posture for local development

### Key Findings

**Root Cause:** Three distinct Aspire security controls were conflated:
- `DOTNET_DASHBOARD_UNSECURED_ALLOW_ANONYMOUS` → Dashboard **UI** access
- `ASPIRE_ALLOW_UNSECURED_TRANSPORT` → Protocol layer (HTTP vs HTTPS)
- `Dashboard__Otlp__AuthMode` → OTLP **API key authentication**

The warning is triggered by `OtlpAuthMode.Unsecured` in `DashboardOptions`, which is set by AppHost code — not by environment variables in `launchSettings.json`.

**Critical Learning:** Environment variables in the parent AppHost process do NOT automatically propagate to the child dashboard process. The AppHost controls dashboard configuration programmatically.

### Decision

**Accept the warning as expected behavior in local development:**
- OTLP endpoint is intentionally unsecured for localhost
- Suppressing the warning requires API key configuration (unjustified for local dev)
- The warning correctly informs developers of the security posture
- Production guidance: use `Dashboard__Otlp__AuthMode=ApiKey` with secure API key distribution
