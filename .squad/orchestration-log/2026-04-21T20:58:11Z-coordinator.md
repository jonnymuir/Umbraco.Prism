## Work Summary

Identified and fixed critical server-side validation bug affecting form submission and error handling flow.

## Bug Description

### Issue
Server-side validation errors in workflow forms were not being properly communicated to the user on re-render after PRG redirect.

### Root Cause
**Location:** `src/UmbracoPrism.TestSite/Controllers/WorkflowPageController.cs`

The validation response logic was checking:
```csharp
if (response.ResponseState == "error")
{
    // Handle error
}
```

This check failed for validation errors where `ResponseState` was correctly set to `"validation_error"` by the backend, not the generic `"error"` state.

### Symptoms
- Form submitted with validation errors (e.g., missing required field)
- Backend returned `"validation_error"` response with field problems
- Response was processed but errors were not passed to TempData
- On PRG redirect, form re-rendered without error messages
- User saw clean form, not the validation failures they made

## Solution

### Fix Applied
Changed validation check in POST handler:
```csharp
// Before
if (response.ResponseState == "error")

// After
if (response.Problems.Count > 0)
```

### Why This Works
- `response.Problems` is populated by backend for any validation errors
- Works for `"validation_error"`, `"error"`, or any state with problems
- State-agnostic: focuses on actual problems, not response state enum
- Correctly triggers TempData population for PRG redirect

### Impact
- Form values now preserved in TempData
- Field-level error messages displayed on re-render
- User sees exactly which fields failed validation
- Form is pre-populated with submitted values for correction

## Affected Code Path

1. User submits workflow form with validation errors
2. Backend processes and returns `ResponseState = "validation_error"` with `Problems` array
3. Controller receives response
4. **FIX:** Checks `Problems.Count > 0` instead of state equality
5. TempData populated with form state and errors
6. PRG redirect to GET handler
7. Form re-renders with:
   - User's submitted values
   - Error messages on failed fields
   - Hints for correction
