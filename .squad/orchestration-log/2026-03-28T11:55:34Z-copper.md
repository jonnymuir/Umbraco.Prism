## Task: Biometric Auth Security Threat Model

**Status:** Completed

**Output:** Security threat analysis section merged into `/Design/biometric-auth.md`.

### Deliverables

**Decision:** Adopt Prism-issued device credentials instead of storing Entra refresh tokens on-device.

**Threat Model Summary:**
- Device lost/stolen with biometric bypassed (Medium likelihood, High impact)
- Root/jailbreak credential extraction (Low likelihood, High impact)
- Cross-tenant credential leak (Low likelihood, Critical impact)
- Entra refresh token theft if stored (Medium likelihood, Critical impact)
- Biometric enrollment by attacker (Low likelihood, Medium impact)
- Capacitor bridge compromise (Very Low likelihood, Medium impact)
- Credential replay after revocation (Low likelihood, Medium impact)
- Extended credential lifetime abuse (Medium likelihood, Medium impact)

**Server-Side Controls:**
- Device Registry Table with revocation support
- Device Credential Exchange Endpoint (/api/prism/device/exchange)
- Admin Revocation API
- Automatic 30-day credential expiration

**Multi-Tenant Isolation Requirements:**
- Keystore key naming pattern: `prism_device_cred_{tenantId}_{userId}`
- Credential scoping with tenant_id JWT claim
- Device registry isolation per tenant

**Hard Constraints:**
1. No Entra Refresh Token Storage in device keystore
2. Single-Tenant Binding (tenant ID in JWT)
3. Server-Side Registry (central control)
4. Bounded Lifetime (max 30 days)
5. Biometric Failure Handling (fallback to full OIDC)
6. Keystore Isolation (multi-tenant support)

**Implementation Phases:**
- Phase 1 (MVP): Device credential issuance, registry, exchange endpoint, native integration
- Phase 2 (Hardening): Admin UI, configurable lifetime, registration approval flow, anomaly detection
- Phase 3 (Advanced): Credential rotation, device fingerprinting, compliance reporting

**Open Question for Tom Nook:** Refresh token encryption key scoping (global vs per-tenant).
