## Context

Brewster conducted an Umbraco 17 specialist review of the current workflow pages, supporting components, and dashboard against idiomatic Umbraco v17 patterns.

## Outcome Summary

**Overall Assessment:** The current architecture is a strong fit for Prism and Umbraco 17, with the boundary between Prism and Umbraco clearly observed.

### Key Findings

1. **Route-hijacked pattern is correct**
   - `WorkflowPageController`, `WorkflowHubController`, and `MemberDashboardController` follow Umbraco 17 conventions
   - Server-rendered Razor with content-resolved navigation is idiomatic

2. **Missing typed models and ModelType attributes**
   - Route hijackers omit `[ModelType("alias")]` attributes
   - `HomePage.cshtml` is untyped and references unmapped aliases like `cardImage`
   - These should be added to catch field mapping errors early

3. **Dashboard routing has hardcoding debt**
   - `/dashboard` is hardcoded in `MemberDashboardController` instead of using `CurrentTemplate()`
   - `MemberDashboardController` uses direct view path instead of publishing through Umbraco's template system

4. **Document type design is skeletal**
   - `PrismContentTypeSeeder` creates minimal types without richer page fields or explicit child relationships
   - Thinner than a reference Umbraco site but serviceable for demo/MVP

5. **Backoffice dashboard has muddled information architecture**
   - Uses correct v17 extension stack (manifest JSON + Lit/UUI web components)
   - Registers custom `Prism.Section` but actually renders into `Umb.Section.Content`, so custom section is unused

6. **Unfinished demo surface area**
   - `workflowDemoPage` references non-existent `prism-workflow-shell` bundle
   - Instance-picker UI present in Razor but never activated by controller logic
   - Should be completed or clearly marked as in-progress

### Pattern Established

**Strongest Design Boundary:**
- Umbraco owns authored routes and page shell
- Prism owns tenant/auth/session plumbing
- Business App is the source of truth for workflow state

Keep these components aligned to the boundary:
- `src/UmbracoPrism.TestSite/Controllers/WorkflowPageController.cs`
- `src/UmbracoPrism.Core/Controllers/WorkflowHubController.cs`
- `src/UmbracoPrism.Core/Services/BusinessAppWorkflowClient.cs`

### Follow-up Actions (Priority Order)

1. Add `[ModelType]` attributes to all route hijackers
2. Fix `HomePage.cshtml` type mapping and alias references
3. Refactor `MemberDashboardController` to use `CurrentTemplate()`
4. Complete or mark `workflowDemoPage` as in-progress
5. Consolidate or hide the unused custom backoffice section
6. Model more page fields and child relationships in content type seeder
