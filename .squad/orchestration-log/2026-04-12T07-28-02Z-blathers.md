# Blathers — Keycloak localhost redirect_uri diagnostic (2026-04-12T07:28:02Z)

## Context
Blathers diagnosed and resolved a runtime Keycloak 26 issue where the OIDC sign-in flow was rejecting localhost `redirect_uri` values despite them being configured in the Keycloak client.

## Diagnosis
- Traced live authorize requests during TestSite OIDC sign-in flow
- Confirmed Prism sends expected localhost redirect URIs (`https://localhost:44345/signin-oidc`, `http://localhost:9250/signin-oidc`)
- Identified that Keycloak 26 rejects `localhost:*` wildcard redirect rules even when imported in the client JSON
- Root cause: Keycloak persists wildcard config but does not honor it during runtime redirect URI validation

## Resolution
1. Updated `keycloak/realm-export.json` to replace wildcard `localhost:*` patterns with exact TestSite launchSettings URLs
2. Applied the following redirect URIs:
   - `https://localhost:44345/signin-oidc`
   - `http://localhost:9250/signin-oidc`
3. Applied corresponding web origins to match
4. Updated `ASPIRE_DEV.md` with redirect URI convention documentation

## Validation
- Build succeeded after config updates
- Core tests passed
- Local Keycloak now accepts sign-in after exact redirect URIs were applied
- No regression in existing OIDC flow

## Decisions Made
- Documented as standing effect: pin local Keycloak client redirect URIs to exact TestSite launchSettings URLs
- If TestSite ports change in repo config, `keycloak/realm-export.json` must be synchronized
