## Sprint Objective

Implement full support for all three `instancePolicy` values (single, multiple, prompt) in the workflow engine, completing the partial scaffolding already in place.

## Context

The workflow definition schema had three policy options, and the view layer (workflowPage.cshtml and _WorkflowHub-InstancePicker.cshtml) plus ViewModel (PrismWorkflowViewModel.ShowInstancePicker) were already correctly built. Only backend logic needed to be connected.

## Work Stream 1: Blathers — Backend Implementation

### Scope
- GetCurrent method signature and logic
- API endpoint parameter handling
- Client interface updates
- Controller integration
- WorkflowInstanceSummary property

### Key Decisions
1. **Parameter Passing:** JSON body optional; backward compatible
2. **Access Control:** Validate tenant+user ownership for instanceId parameter
3. **Terminal States:** Prompt policy treats completed instances as "no active" scenario
4. **Lookup Key:** Only update on `action="start-new"` in prompt policy
