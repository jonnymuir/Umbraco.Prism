## Isabelle: Remove btn-mobile-signin Pattern

**Task:** Clean up duplicate sign-in button on unauthenticated hero (bug report from Jonny)

**Root Cause:**
- `btn-mobile-signin` anchor rendered alongside primary `btn-primary` "Sign In" CTA
- Hidden in desktop mode (`display:none`)
- Revealed in mobile mode (`html.prism-mobile`)
- Result: Two "Sign In" buttons in body when running in Prism mobile shell

**Decision:**
- **Do not use hidden/revealed buttons as a pattern for mobile-specific auth CTAs**
- Primary CTA already gets full-width layout in mobile mode → no replacement needed
- If a mobile variant is ever needed (e.g., biometric shortcut), introduce as distinct named element with unique label

**Changes:**
- Removed `btn-mobile-signin` anchor element
- Removed `mobileAuthHref` and `mobileAuthLabel` C# variables
- Removed CSS rules: `.btn-mobile-signin { display:none }` and `html.prism-mobile .btn-mobile-signin { display:inline-flex }`

## Kicks: Biometric Client-Side Flow Implementation

**Task:** Fix missing biometric client-side flow — Jonny signed in via Entra but no Face ID prompt appeared

**Root Causes Fixed:**

1. **`biometric-bridge.ts` bug:** `authenticate()` called `response.json()` on `/exchange` response, but server returns `Ok()` (empty body) + `Set-Cookie`. JSON parse threw silently, breaking biometric auth.
   - **Fix:** Removed JSON parsing, added `credentials: 'include'`, changed return type to `Promise<void>`

2. **No startup biometric flow:** `www/index.html` bootstrap generated by `MobileBundleService` navigated directly to start URL without attempting biometric auth first.
   - **Fix:** Added `tryBiometricSignIn()` async function that runs before `canReachStartUrl()`, using `window.Capacitor.nativePromise()` to call native plugins

3. **No enrollment trigger after Entra login:** Users never prompted to enable Face ID/Touch ID after first successful Entra authentication.
   - **Fix:** `PrismBrandingMiddleware` injects `<script id="prism-biometric-enroll">` into authenticated mobile pages when `tenant.AllowBiometricLogin && user.IsAuthenticated`. Handles full registration flow: biometric confirm → POST `/register` → SecureStorage store → enrollment fingerprint save

4. **Missing CORS on `/exchange`:** Capacitor origin (`capacitor://localhost` iOS, `http://localhost` Android) calling `/exchange` cross-origin would fail without headers.
   - **Fix:** Added `Access-Control-Allow-Origin` + `Access-Control-Allow-Credentials` headers, `[HttpOptions("exchange")]` preflight handler

**Technical Insights:**
- `www/index.html` is vanilla JS (no ES module bundler) → use `window.Capacitor.nativePromise(pluginId, method, options)` to call plugins
- `@aparajita/capacitor-secure-storage` applies `capacitor-storage_` prefix internally; data is JSON-encoded
- `PrismMemberCookie` is `SameSite=Lax` → Set-Cookie IS stored from cross-origin fetch + IS sent on top-level navigation
- `/exchange` returns `Ok()` + `Set-Cookie`, NO `sessionToken` — session established via cookie alone

**Build Status:** ✅ Clean

**Decision Record:** `.squad/decisions/inbox/kicks-biometric-client-flow.md`
